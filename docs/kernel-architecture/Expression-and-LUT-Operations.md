# Expression and 1D LUT operations

`numeric.sample_expression`, the three `numeric.sample_expression_<profile>` keys and `lut.apply_1d` use fixed CPU tasks. The unsuffixed sampler can produce queries for the LUT operation. Each selected output tile has an independent dense allocation; preparation establishes exact read slots and scratch before execution. The [Chinese mirror](zh/Expression-and-LUT-Operations.zh.md) follows this contract.

## Unsuffixed expression sampler

`numeric.sample_expression` takes one Result with exactly one tensor under any valid schema ID/version/member key. Its unbatched Float64 sample shape is `[K]`, with `1 <= K <= 256`. Required parameters are String `expression`, Int64 `count` in `[1,1048576]`, Float64 `start` and Float64 `step`. Start must be finite and step finite and positive. For count>1, `fma(count-1,step,start)` must be finite and greater than start. These static conditions are checked during preparation. Output port `value` uses `photospider.tensor` v1/member `samples`, ordinary Float32 `[count]`, without attached sampling labels.

The bounded grammar accepts decimal/scientific literals, `x`, `c[index]`, parentheses, unary signs, binary `+ - * / ^`, unary `abs`, `sqrt`, `exp`, `log`, `sin`, `cos`, and binary `min`, `max`. Power is right-associative and binds above unary signs: `-2^2=-4`, `2^-2=.25`, `2^3^2=512`; `0^0=1`. Static parsing checks every coefficient index against K and rejects other identifiers, malformed calls, hexadecimal/NaN/infinity literals, source longer than 4096 bytes, more than 256 AST nodes or height above 32. Parentheses do not add nodes.

Preparation parses once and owns the immutable AST. Each selected output tile reads the complete coefficient tensor, including entries not referenced by the AST. The task copies at most 256 coefficients into its 4096-byte preallocated workspace; the other 2048 bytes hold postorder values. It computes only its selected coordinates using global `fma(i,step,start)`, evaluates Float64 operations in source order and narrows once to Float32. Elementary/transcendental evaluation uses the host Float64 implementation; this key has no strict cross-platform correct-rounding claim. Rounding is nearest-even with gradual underflow.

Finite coefficients, finite intermediates/results and valid mathematical domains are caller preconditions. Runtime performs no coefficient scan, division/domain validation or final finite-range check, and promises no domain diagnostic. Changing bindings reuses the AST and creates independent Run-owned results. Empty selection emits no task or payload read. Cancellation is checked during coefficient copying, at most every 32 AST nodes and every 256 output samples.

## Profile-specific named-coefficient sampler

The suffixed family accepts dynamic scalar start/end and separately named coefficients, with required static `expression`, `coefficient_names`, `count` and `dtype`. Values is ordinary `[count]` in Float32/64; axis is an atomic Float64 `[3]` tuple. Each selected values tile has a fixed task; axis has another task. Count one excludes end payload while retaining its schema, and axis excludes all coefficient payloads. All schemas remain checked.

Its separate grammar adds pi/e, tan and named identifiers, and uses `ln` rather than the unsuffixed key's `log`. Strict evaluates each primitive with RN64 before its parent. Accelerated four-lane batches enclose the complete strict reference and replay uncertain samples, preserving the final FP32-scaled error bound. Numeric domains and selected-coordinate precision are unchecked caller preconditions. Selected outputs share one IR call's publication outcome.

The helper is [`sample_expression_node`](../../plugins/ops/include/photospider/ops/numeric/expression.hpp). It authors one WorkflowNode and canonicalizes the exact name/connection map. See [NUM-01](../built-in_ops/01-numeric/op_specs/NUM-01_sample_expression.md) and [fixed expression execution](../built-in_ops/01-numeric/expression-execution.md) for the complete sampling, numerical and resource contract.

## Linear LUT application

`lut.apply_1d` takes a Float32 query Result and an unbatched Float32 rank-one table Result with at least two samples. Each has exactly one tensor under any valid schema/member key. Query shape may include batch axes and multiple channels. Required static parameters are Float64 `sample_origin`, finite positive Float64 `sample_step`, and String `out_of_domain` (`reject` or `clip`). Origin and `fma(N-1,step,origin)` must be finite, and the latter must be greater than origin. Output port `value` uses `photospider.tensor` v1/member `samples`, preserves the query's cell shape and batch axes, and has ordinary cell axes rather than inheriting spatial/atomic facets.

Each selected output tile declares its intersecting query tiles using the query's own grid, plus every table tile. Runtime data chooses a table index, so the complete table is the static address superset. Runtime reads only the chosen endpoint or neighboring pair; it does not pack or numerically scan the whole table. Multiple tasks share immutable input owners. Each LUT invocation uses zero scratch and bounded stack state; `scratch_count=0` permits a null scratch array. Empty selection declares no payload task.

Finite queries and consumed table values are caller preconditions. Under `reject`, queries must lie within the closed table domain; outside-domain diagnostics are not guaranteed. Under `clip`, out-of-domain finite queries return the nearest endpoint. Endpoint queries preserve endpoint values, including signed zero. Interior evaluation uses compensated Float64 interpolation. It keeps the finite `[0,2^53)` position guard before integer conversion, bounded neighboring-segment correction, finite representable candidate checks and a discarded-compensation limit of one eighth of a Float32 ULP. These algorithmic address/precision guards can return OperationFailed when interpolation cannot establish its result. They are distinct from general sample-domain validation. Table values may be signed or HDR; no color-gamut interpretation is imposed.

## Preparation, ownership and errors

Preparation checks static schemas and parameters, canonical Host output views, exact complete input tile membership, empty task parameters and scratch sizes. Physical views retain the Plan's checked offset/stride contracts; raw reads support compatible negative/zero strides and unaligned storage. Runtime creates no payload buffer. Root admits selected output storage, maximum scratch per CPU lane and executor metadata before issue. A sparse LUT query still requires the complete declared table, while a sparse expression allocates only selected output tiles.

All tasks of a call share its publication outcome. Source, resource, backend and cancellation failures prevent successful call publication and preserve their operational status categories. Accepted work drains before unpublished storage is released. Concurrent Runs share only immutable preparation and inputs; output allocations and expression scratch are private. Successful Result owners can outlive ExecutionContext. Invocations restore floating modes and exception flags. There is no content-cache or repeated-demand identity guarantee in this path.

Malformed grammar or static parameters return InvalidArgument; incompatible dtype, shape or task signature returns TypeMismatch. Input/output structural checks remain mandatory. Numerical precondition violations have no promised diagnostic; LUT's address and precision guards remain fallible arithmetic. No automatic sample validator or implicit layout conversion is added.

## Behavior validation

Temporary public checks should compare sampler arithmetic against independent stepwise references and LUT outputs against exact rational interpolation. Include grammar/AST/index limits, global indices, sparse maximum count, full coefficient/table dependencies, batch/atomic query geometry, endpoint/raw-zero behavior, cancellation and malformed preparation. Verify actual sampler-to-LUT composition, binding replacement, artifact round trips, concurrent Runs, low-resource rejection, null zero-scratch ABI invocation and returned owners after context destruction. Numerical evidence and platform performance claims remain separate.
