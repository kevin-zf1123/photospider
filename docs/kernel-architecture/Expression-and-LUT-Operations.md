# Expression and 1D LUT operations

The default registry exposes the unsuffixed Result operation `numeric.sample_expression`, the profile-specific `numeric.sample_expression_<profile>` family, and the Result operation `lut.apply_1d`. The unsuffixed sampler can feed a SampledSignal query into the one-dimensional LUT operation. The accepted composition boundary is [ADR 0020](../adr/0020-composable-operation-foundations.md); this page describes the current registered keys. The [Chinese mirror](zh/Expression-and-LUT-Operations.zh.md) follows the same contracts.

## Unsuffixed expression sampler

`numeric.sample_expression` takes one Result input containing exactly one tensor and no fields. The tensor may use any structurally valid schema id, version, and member key; its unbatched Float64 sample shape is `[K]`, where `1 <= K <= 256`. Its required static parameters are String `expression`, Int64 `count` in `[1,1048576]`, Float64 `start`, and positive Float64 `step`. Output port `value` is a Result using `photospider.tensor` v1/member `samples`, Float32 shape `[count]`, and SampledSignal metadata. The sample axis uses the supplied start and step, and the value channel is named and role-tagged `value`. The constructor supplies no defaults.

The expression grammar accepts decimal or scientific numeric literals, `x`, `c[index]`, parentheses, unary `+` and `-`, binary `+ - * / ^`, unary `abs`, `sqrt`, `exp`, `log`, `sin`, `cos`, and binary `min`, `max`. Power is right-associative and binds more tightly than unary minus: `-2^2` is `-4`, `2^-2` is `0.25`, and `2^3^2` is `512`; `0^0` is `1`. The parser rejects arbitrary identifiers, hexadecimal literals, `NaN` and infinity names, malformed indices and malformed function calls. Source is limited to 4096 bytes, 256 AST nodes and AST height 32; parentheses do not add nodes.

The operation uses Whole execution. A nonempty request asks for Data, Validation, and Descriptor support (role 13) for its complete coefficient tensor. Empty requests perform static preparation without reading payload. Static preparation parses the expression into an immutable AST; runs can reuse that prepared state while supplying new coefficients. The kernel validates every coefficient, including unused entries, and charges its 4096-byte evaluator workspace and output through the Root resource allocator. It requires finite `start` and finite positive `step`. When `count > 1`, `fma(count-1,step,start)` must be finite and greater than `start`. The sampler computes each coordinate as `fma(i,step,start)` and evaluates in a controlled Float64 nearest-even, gradual-underflow environment. Each subexpression must be finite, division by zero and function-domain errors fail, and the final value must fit finite Float32. Cancellation is checked during evaluation and before publication; failure discards unpublished output and restores the caller's floating-point environment.

## Profile-specific named-coefficient sampler

`numeric.sample_expression_strict`, `numeric.sample_expression_accelerated_apple_silicon` and `numeric.sample_expression_accelerated_x86_64` take dynamic scalar `[1]` inputs. Input 0 is `start`, input 1 is `end`, and each remaining input is a coefficient whose name appears in the required String `coefficient_names`. The helper `ps::numeric::sample_expression_node` builds this form from an expression and a map of named coefficient inputs.

Required static parameters are String `expression`, String `coefficient_names`, Int64 `count` in `[1,1048576]`, and String `dtype` (`float32` or `float64`). The `values` output uses `photospider.tensor` v1/member `samples` with shape `[count]` in the selected dtype. The `axis` output uses the same schema/member and is Float64 `[3]`, containing start, end and computed step when count exceeds one; for count one it contains `[start,start,0]` and declares one atomic trailing axis. A values request with count one does not read the end and still reads the coefficients used by the expression. For a count greater than one, values needs finite distinct endpoints and representable adjacent coordinates; evaluated coefficients must be finite. Both outputs use Whole execution and publish through Root-admitted Result transactions. An axis-only request skips coefficient evaluation; an empty request skips payload work.

This family has its own parser and function set. It accepts decimal/scientific literals, `x`, `pi`, `e`, named coefficient identifiers, parentheses, unary `+ -`, binary `+ - * / ^`, unary `abs`, `sqrt`, `exp`, `ln`, `sin`, `cos`, `tan`, and binary `min`, `max`. `log` is the function name on the unsuffixed Result key; the profile-specific keys use `ln` and also provide `tan`, `pi` and `e`. The suffix selects a CPU numeric profile. Unsupported host profiles fail during preparation. Strict evaluation uses the same left-to-right Float64 expression order and rounds once to the requested output dtype. Accelerated profiles certify candidate results against the fixed strict result and replay uncertain samples through the strict evaluator. They preserve the profile's result across Whole and regional requests. These keys have two named outputs and dynamic endpoint bindings; they do not share the unsuffixed Result sampler's coefficient-vector input or static start/step parameters.

The public workflow helper is declared in [`numeric/expression.hpp`](../../plugins/ops/include/photospider/ops/numeric/expression.hpp). Consumers include it as `photospider/ops/numeric/expression.hpp` through the header-only `Photospider::ops_headers` target, linked together with `Photospider::kernel`. It produces an ordinary `WorkflowNode` with `values` and `axis` outputs. The helper serializes free coefficient names in bytewise-sorted order and rejects missing, unused or duplicate names before adding the node.

## Linear LUT application

`lut.apply_1d` takes two Result inputs, each containing exactly one tensor and no fields. Both inputs may use any structurally valid schema id, version, and tensor member key. Input 0 is a Float32 SampledSignal query; its sample shape may include batch axes and may have multiple channels. Input 1 is an unbatched Float32 rank-1 table. The table must carry a single-channel SampledSignal or Lut domain and contain at least two samples. The query sample-value unit must match the table sampling-axis unit; the query axis unit and table-value unit are independent. The required String parameter `out_of_domain` is `reject` or `clip`. Output port `value` is a Result using `photospider.tensor` v1/member `samples`, Float32, with the query's sample shape and batch axes, and empty facets.

The operation uses Whole execution. A nonempty request asks for Data, Validation, and Descriptor support (role 13) for both complete inputs; Empty requests do not read payload. Static preparation validates the query and table metadata and prepares immutable operation state. The Result transaction publishes the complete output only after successful evaluation. The table domain requires finite origin, finite positive sample step and a finite increasing endpoint from `fma(N-1,step,origin)`. The operation returns exact table endpoints for endpoint queries and uses compensated Float64 interpolation inside the domain. It rejects an interior index at or above `2^53`, arithmetic that cannot be represented, or discarded compensation larger than one eighth of a Float32 ULP before writing output. Values outside the table domain fail under `reject` and return the nearest table endpoint under `clip`. Signed table values and HDR values are supported; the operation does not clamp to a color gamut or establish table-value semantic metadata on its output.

## Errors and validation

Malformed expression syntax and invalid static parameters return `InvalidArgument`. Type, shape, or semantic mismatches return `TypeMismatch`. Generic expression coefficients are checked during evaluation, so a nonfinite coefficient returns `OperationFailed`; undefined math, coordinate collapse, interpolation precision loss, and output overflow also return `OperationFailed`, with a sample index where available. Typed LUT inputs are validated completely during their Need; a nonfinite typed source sample can return `InvalidArgument` with `FailureReason::InvalidDomain` and its source `input_id`, including when the sample is outside the selected interpolation stencil. Empty demand skips payload validation. Cancellation and resource exhaustion keep their own status codes. The host validates Result metadata before payload execution, including the semantic contract and compatible operation declarations.
