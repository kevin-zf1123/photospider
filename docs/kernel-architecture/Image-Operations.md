# Image operations

## Scope and current availability

Structured `Result` is the public semantic, input, output, publication, and ownership contract for image samples. A Result schema declares typed image slots backed by `PlanarImage`; it may also declare primitive fields. Ordinary non-image numeric `Value` remains valid. An image-looking `Value` facet or a registration in the operation catalog does not make a Value callback a Result image operation.

The current kernel package is 0.29.0, WorkflowDocument schema 4, and OperationTraits version 21. The standalone planar callback table, planar image executor, and planar workflow binding were removed. Legacy planar C entry points v1-v3 are rejected. Production operation code has not been rewritten to the Result image contract. The table below describes current source and runtime availability; Result use is available through test-defined minimal operations and the public example.

Other production operations may remain registered while the compiler rejects their legacy structural-image Value contract. Registry presence is not runtime image support.

## Result image contract

A typed image slot carries a descriptor for one frame/layer, a planar physical layout, semantic facets, and a bounded number of frame/layer samples. Its logical coordinates are `{frame, layer, descriptor axes...}`; frame and layer are separate axes, not color channels. A Result can mix typed image slots and primitive fields under one schema. Do not encode image bytes as `ResultFieldSpec` records.

The compiler resolves the selected named output and its input projection. The Result continuation requests only declared inputs; a callback can read Control samples and then request the Data image support selected by those values. The published relation records both. Dirty transpose uses that same relation, so consumed controls can select new support without treating unrelated inputs as dependencies. `Exact`, `Conservative`, and `Unknown` keep their declared proof meaning.

The Result owner retains schema, certified descriptor facts, backing, relations, and consumed input owners. Admission uses the execution root for work, stages, I/O, relation/maps, payload, and owners. A failed publication is sticky. Cancellation and stale execution retire active callbacks before releasing their phase state. See [Structured Results and image slots](Global-Results.md), [Dependency Data](Dependency-Data.md), and [Tensor Storage and Region Access](../kernel-specs/Tensor-Storage-and-Region-Access.md).

## Public executable path and limits

[`examples/unified_result_workflow`](../../examples/unified_result_workflow/README.md) demonstrates a public workflow using test/example-only minimal operations. It selects an image Result output and a numeric output, requests image regions, and exercises a dynamic support change. Current built-in image operations remain constrained as listed above. This does not disable ordinary numeric Values or non-image structured Results.
