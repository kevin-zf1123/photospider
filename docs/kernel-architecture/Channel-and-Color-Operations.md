# Channel and color operations

[Chinese reader version](zh/Channel-and-Color-Operations.zh.md).

Bundled format operations use Result ports; their invocation protocols are described by family below. A Result carries structure and samples, with no attached color, alpha, transfer, sampling or encoding description. Every operation receives the interpretation it needs as explicit static parameters. An explicit description is configuration, not proof of sample validity. The kernel does not reject a connection solely because callers assign different meanings to structurally compatible data.

Public workflow helpers and runtime operations belong to `Photospider::ops`. Consumers link that target, which depends on `Photospider::ops_sdk`, `Photospider::ops_headers` and the kernel. Shared descriptions, codecs, resource wrappers, exact domain mathematics and `format::edit_description` belong to `Photospider::ops_sdk`. The SDK uses only kernel public interfaces. The `TensorDescription` codec selects canonical TDM4 or TDM5 according to its coordinate records; see [Tensor descriptions](Tensor-Semantic-Metadata.md).

## Structural channel operations

Extraction, assembly and editing preserve UInt8, Int8, UInt16, Int16, Int64, Float32 and Float64 sample bits, including NaN payloads and signed zero. They do no color conversion, alpha normalization or sample-domain scan. All axis indices are relative to cell axes, excluding the Result batch prefix. Full sample rank is at most eight. Assembly accepts 1..1024 single-tensor Results with no fields and matching nonscalar batch prefixes/nonchannel shapes; its input/output sample limit is 2^40. Extraction instead follows Result backing and requested-region representability, without a family-wide dense product limit.

Extraction uses fixed invocation ABI 8, with one CPU Host task per selected output tile. Lowering maps output coordinates to the selected channel and closes that region through the source grid. The kernel copies only selected coordinates; physical input tiles may also contain other channels. keepdims=false removes a cell axis and adjusts atomic trailing count when needed, while preserving the batch prefix. Preparation verifies exact read slots, output geometry and zero scratch. Legal source views may have signed/zero strides or unaligned offsets; DenseHost uses explicit import COPYs. Auto/materialize copy bits to independent dense output tiles. A nonempty view task depends only on source schema and fails InvalidArgument/InvalidDomain; Empty retains static checks without payload tasks. Cancellation is polled between at most 256 samples. Split verifies the complete schema and spatial topology at compilation, including forward producer references; outputs carry no description.

Assembly inserts, concatenates or maps channel indices. Every connected input participates in static Descriptor checks; payload reads follow only selected coordinates. Mapped records contain input, match, selector and destination, with every destination filled exactly once. There is no output_description or destination_component parameter. Replacement reads original immutable inputs simultaneously; an overwritten base value is not read unless another requested destination selects it. Scalar records explicitly repeat unbatched shape `[1]` values; an ordinary plane is not implicitly broadcast.

Assembly uses fixed ABI 8, with one zero-scratch CPU task per selected output tile. Lowering maps destination spans to source regions and unions source-grid tiles per port without bridging unused source gaps. Complete output tiles may include several channels; input tiles may cover additional samples. Unused ports are schema-only. Auto/materialize copy exact bits to independent dense outputs; nonempty view is schema-only and fails InvalidArgument/ViewUnavailable, while Empty has no payload task. Preparation verifies exact slots and bounds expected closure by the actual supplied slots before expansion. Runtime uses immutable span/slot tables, fixed-size coordinates and one cached view, polling cancellation between at most 256 samples. Failed calls publish no partial result, and output owners survive source/context teardown.

`channel.literal_like_<profile>` uses fixed invocation ABI 8. Each selected output tile is one CPU Host task with a `schema_reads` dependency on the input and no payload reads. Preparation verifies the source schema assertion, bits, axis/keepdims, layout, output tile geometry and zero scratch. Auto/materialize repeat exact same-dtype bits into preallocated outputs, including signaling NaN representations; view returns InvalidArgument/InvalidDomain during nonempty execution, while Empty performs no fill. Cancellation is polled between at most 256 writes. Output and call-retirement ownership follow the fixed executor protocol. `channel.scalar_literal_<profile>` uses a zero-input, zero-scratch fixed task to produce one same-dtype `[1]` tile from exact native bits.

## Alpha

FMT-04 described association requires an explicit RGB/Gray group with internal alpha and the appropriate source association. Its fixed ABI 8 tasks assume valid semantic colors/alpha and finite rounded results, including the semantic zero-alpha preconditions. Formulas, rounding, underflow and raw IEEE behavior remain in the family specification. Without a description, raw calls use explicit components and internal, plane or scalar weights. FMT-04 never implicitly inserts alpha and never exports an alpha relationship in metadata.

FMT-05 requires a straight interpretation supplied by the caller. Set uses fixed ABI 8 with Float32/Float64. Semantic color/alpha validity belongs to the caller. It copies each slot from its own source without a color-to-alpha validation read; complete output tiles determine actual source closure. Set auto/materialize produce independent dense output with zero scratch; nonempty view has schema-only dependencies and fails ViewUnavailable. Extract/remove preserve all seven copy dtypes without a new sample-domain scan. Existing alpha extraction copies exact bits; `alpha_encoding` only configures the missing-alpha opaque fallback, whose coverage-one code must be exactly representable.

Channel-bearing removal uses mapped assembly, structural assertions and its layout policy. Axis-free missing-alpha identity uses `core.identity`, returns `value`, adds no source assertion and ignores the helper layout policy; core.identity emits explicit COPY tasks. A downstream consumer must receive its own description. Read alpha does not become published alpha coverage; later consumers request needed samples normally.

## Numeric format and transfer

FMT-06 implements all 49 supported dtype pairs through fixed invocation ABI 8. Rescale defaults to true with independent dtype-derived source and target intervals; pure cast rejects ranges and axis. Per-channel range tables use explicit cell axes. The exact affine result rounds once to the destination. Reject requires representable rounded results; integer targets require finite source samples. Clip and floating NaN/Inf mapping remain numerical result rules. The Result retains structural schema identity, tensor key, shape and batches, changes dtype and sets `atomic_trailing_axes=0`. No decoder is propagated. One task per complete output tile reads its source-grid closure and writes an independent dense allocation. Identity copies bits with zero scratch; nonidentity uses fixed exact arithmetic scratch. Nonempty identity view has a schema-only dependency and fails ViewUnavailable. SIMD/SME paths share the strict numerical contract and require separate native-dispatch evidence when measured.

FMT-09 with `input_description` requires a unique group and forbids raw axis/components. Decode can resolve its full curve from that configuration; encode requires a target curve and a linear source interpretation. Without a description, explicit components and curve are required; index lists require axis. Curve-specific units/reference checks are retained. Output keeps shape/dtype and sets `atomic_trailing_axes=0`, with no transfer label.

FMT-09 uses six fixed invocation ABI 8 CPU keys. Semantic finite-input, curve-domain and finite-output requirements are caller preconditions over complete retained output tiles. Linear and gamma=1 copy bits; bypass tiles need zero scratch. Auto/materialize write independent dense tiles. Nonidentity forced view rejects statically; nonempty identity view has a schema-only dependency and fails ViewUnavailable.

General transfer tasks gather 64 points and use declared fast/compact/wide scratch. Rational branches compile to bounded degree-two polynomials with exact coefficients; transcendental branches use directed interval refinement with explicit status. Internal precision/capacity retry is distinct from cancellation or caller resource failure. Invocation numerical state allocates no heap storage, is isolated between Runs and restores the floating environment. Gamma=2 retains its signed square/sqrt SIMD path with a smaller fixed gather block.

## Basis, white and model conversions

FMT-10 applies exact RGB/XYZ matrices and explicitly selected XYZ Scaling, Bradford, CAT02 or CAT16 adaptation. Described calls require a selected RGB/XYZ group; raw calls require axis, ordered components and geometry. Its nine CPU keys use fixed invocation ABI 8. Nonidentity rows consume all three source terms, including zero coefficients; whole-matrix identity reads only the corresponding sample. Semantic finite-input/output conditions are caller preconditions over retained output tiles. Source closure uses the input grid, and auto/materialize write independent dense tiles. Nonidentity forced view rejects statically; exact-I nonempty view reads only schema and fails ViewUnavailable. Bypass alpha/AOVs are exact copies. Transfer, exposure, gamut and rendering remain separate operations.

D stages its entire graph expansion before mutation. It derives intermediate XYZ configurations from the supplied description and writes them into generated node parameters. It does not recover descriptions from graph edges. A→B and A→C→B retain each node's rounding and failures; same source/target basis does not authorize replacing the composition with identity.

FMT-11 A–R/T supply 57 profile-specific native model keys; S adds three MASK threshold keys. An explicit description can resolve a unique group and permits matching axis/components assertions. Raw calls provide the member's selectors, white, hue unit, NCL coefficients, Gray kind or constants. Raw XYZ→xyY requires white_x/white_y as declared by the implementation. Q removes two selected slots; R expands a Gray slot or inserts an explicit output axis. No output model description is attached.

All 60 keys use fixed invocation ABI 8. Each complete selected output tile maps immutable channel spans to source regions, then unions tiles on the source grid. Pure copies and constants use zero scratch; source-independent tasks retain schema dependencies. Arithmetic uses fixed rational/interval scratch and 64-point gather blocks. Auto/materialize produce independent dense outputs. Q accepts forced view statically, but a nonempty view task is schema-only and fails InvalidArgument/ViewUnavailable; other members reject forced view statically. Empty has no payload task. Semantic numerical validity and T's exact 0/1 selector are caller preconditions. Mathematical black-XYZ and zero-chroma substitutions and raw IEEE behavior remain defined. Static description checks reject an effective non-straight association. Publication follows ordered successful call retirement; this path emits no per-operation numeric reports.

FMT-11 arithmetic owns a fixed rational workspace and one shared checked interval pool for roots, powers, trigonometric functions and atan2. Cancellation and arithmetic capacity failures preserve the first error code/reason and stop further work callbacks. Precision refinement clears only unresolved enclosures; it does not retry cancelled or exhausted arithmetic. Each component evaluation resets its numerical state before use. These arithmetic transitions use explicit status rather than exception storage. Work callbacks are borrowed for the evaluation lifetime, and the workspace cannot be copied or moved because its interval callback refers to its rational state. Kernel preparation verifies exact read slots, output geometry and scratch before invoking this workspace through the fixed CPU entry point.
