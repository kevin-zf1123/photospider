# 任务协作

本约定管理本仓库的开发工作。已接受的公共 ADR 保留产品权威；本文件不修改
CI 或分支保护。

## 范围与完成

从用户当前请求或指定的实时 Issue 开始，读取验收条件、直接依赖、相关代码、
测试和受影响契约。普通实现无需先建 Issue、提案或通读仓库。修改前检查当前
分支、HEAD 和已有改动。

持续完成实现、运行、结果检查和范围内修复，达到约定终点。默认交付本地实现
及验证。复用已有授权，仅询问缺少的实质决策或外部操作权限。仍有验证或修复
时，不在第一版实现后停止。已授权的 Issue 列表或 Project 范围可按依赖连续
完成，无需每项结束后再次询问。

## 前期内核、算子与 workflow 迭代

同时开发内核能力、可使用的算子和可运行的 workflow。通过现有 ABI 增加算子
通常使用 `rapid`。在现有文档或示例附近说明算子名称、输入输出类型与形状、
参数类型/范围/默认值、数值或图像语义及适用的 Region demand。避免新增复制
schema 的第二套算子目录。

新增可组合的算子或 workflow 执行能力时，提供通过公开入口实际运行的最小
workflow 和可检查的预期结果。
复用现有示例或集成测试；修复可复用 workflow 并增加聚焦回归。供 GPT 使用的
示例必须使用已实现 API，已接受的目标契约需明确标注。按算子的实际风险增加
确定性行为测试和错误/边界用例，无需逐算子执行整套内核验证矩阵。

## 验证与审核

默认 `rapid`：聚焦实现、行为测试、局部格式/lint 和 diff 检查。共享公共
API/ABI、安装消费契约、所有权或持久格式变化，以及实际并发、内存、不可信
输入风险使用 `reviewed`。未核验的外部行为和实质不同的方案先核验再取舍。
增加独立的相关代码/契约检查，仅按受影响风险扩大测试。`release` 由用户显式请求。

每个任务保持一个代码写入者。仅在有用时委派独立且范围明确的研究、审核或
CI 分析，不固定代理数量、层级、实现者更换或审核轮次。复审可复用审核者。
修复证据成立、范围内的 `blocker` 和 `required`；建议和范围外问题简要报告，
不自动扩展任务。

后续改动未使检查失效时复用已有结果。CI 失败先读日志，仅在诊断需要时获取
相关 artifact。流程、评分、迁移和状态跟踪检查不进入产品 CI 门槛。

## 交付与记录

commit/push、GitHub 写入、merge、清理和私有 overlay 同步依当前任务授权执行。
按完整行为组织提交和 PR，相关 Issue 可以共用 PR。使用仓库对当前 PR 版本
实际要求的检查。额外远端审核和合并后验证取决于风险或明确交付要求。
不默认 admin merge、绕过保护或为每个 CI 修正创建独立分支；无关且适合独立
审核的基础设施修改可单独提交 PR。

Issues 管理公共交付状态，Projects 同步该状态。已授权写入时，在交付或阻塞
发生实质变化时更新相关状态，简要记录结果、位置、实际验证、剩余事项和下一
动作。仅在阶段或关键依赖变化时更新 Current Development Program。不在
feedback、tracking 和报告中复制进度。私有 OpenSpec 仅显式调用，不构成公共门槛。

公共 ADR 记录决策，架构文档记录已实现行为。同步受影响英文文档与中文镜像。
研究完成不代表设计已被接受，设计接受不证明实现完成。完成表示所请求行为
已在约定交付位置得到验证。私有恢复记录仅按需请求；未提交内容依赖原工作树，
除非可访问的提交或补丁保存了内容。
