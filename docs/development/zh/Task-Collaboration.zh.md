# 任务协作

本公共约定适用于 kernel 和 daemon 任务。产品边界继续由各仓库已接受的 ADR
管理。本约定不修改 CI 或分支保护，审核无需依赖私有代理文件。

## 来源与任务范围

用户指定的实时 Issue 是任务来源。公共 ADR 记录已接受的长期决策，架构文档
记录已实现事实。ADR 草案或已接受的目标必须与现有 API 行为明确区分。Issues
管理交付状态，Projects 提供操作视图。只有阶段、baseline、关键路径或阻塞
原因变化时才更新 Current Development Program。私有 OpenSpec 不定义公开验收。

启动时识别任务类型（研究、决策、实现、交付）、验证模式、验收条件、依赖和
授权终点（本地草案、本地实现及验证、提交 PR、合并后结算）。核验分支、HEAD、
已有改动及相关 PR。这些终点属于协作约定。直接使用既有授权，只询问尚缺的
实质决策或权限。文件修改、测试和审核不自动授权 commit/push、元数据写入、
merge 或清理。

## 执行与验证

默认 `rapid`：定位、完成范围内修改、验证行为并检查 diff。公共 API/ABI、
package/consumer、所有权、持久格式、未核验的外部行为、实质不同的备选决策，
以及并发、内存或不可信输入风险使用 `reviewed`。增加独立的相关代码/spec 审核，
仅按具体风险扩大检查。`release` 只在用户显式要求时启用。

每个任务保留一个代码写入者，共享工作树的任务协调写入。独立只读研究和审核
可以并行。审核分类为 `blocker`、`required`、`suggestion`、`invalid or unverified`；
只有证据成立、范围内的 blocker 和 required 进入修复循环。范围外 finding
报告为待分流事项。普通任务不自动创建 OpenSpec、feedback、tracking、evidence、
分支或 worktree，也不自动运行完整测试矩阵。流程文本检查不进入产品 CI 门槛。

## 状态与完成

远端更新已授权时，维护一个精简的 Issue 当前状态块，记录结果与交付位置、
已检查的验收与验证、剩余事项、阻塞、维护者需决定的具体问题，以及带执行者、
前提和停止位置的唯一下一动作。评论保留讨论。记录实际生命周期：待澄清、
可执行、进行中、待审核、待验收、已完成。阻塞原因单独记录，明确无人执行的
情形。`ready-for-agent` 仅描述可派发程度。

研究交付证据、结论、未知与下一步。决策需要维护者明确接受并达到指定交付
位置。实现需要达到约定交付位置并通过适用测试。父能力需要可重复的集成验收
场景。取消的工作和 Issue 数量不能证明已交付能力或项目总完成百分比。在授权
终点停止，推荐下一 Issue 不构成启动授权。

同一任务负责者先更新 Issue，再同步 Project，核验实际远端变化。没有权限或
更新失败时，说明 GitHub 未更新，并在需要时提供准确的待同步文本。私有恢复
记录按需生成，需要任务授权；不得发布私有路径、凭据、配置或本地报告。
新会话重新核验引用和 Git 状态。未提交内容依赖原工作树，除非已授权保存的
可访问提交或补丁能够恢复该内容。
